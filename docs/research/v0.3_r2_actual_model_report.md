## 3. Key Findings & Discovered Truths

### 1. Proxy Kernel vs. Actual Runtime Discrepancy
A critical methodological insight emerged when comparing the v0.3-R1 unoptimized C++ proxy kernel against the actual ONNX Runtime CPU engine:
- In v0.3-R1, `mobimind_hybrid_10m` was timed at **36.80 ms** by the proxy loop.
- In v0.3-R2, the actual ONNX model runs in **3.65 ms P50** on the Snapdragon 6 Gen 4 CPU.
- **Root Cause**: Production mobile runtime engines like ONNX Runtime utilize vector-optimized kernels (ARM64 NEON, MLAS), cache-blocking matrix layouts, and graph fusions (combining LayerNorm and activation functions). An isolated naive GEMM loop overestimates actual optimized mobile runtime latency by up to $10\times$.

### 2. Empirical Verification of Physical Memory Footprint
In v0.3-R2, the process resident set size (`ru_maxrss`) directly tracked the physical parameter footprint:
- The base runner overhead was $6.47\text{ MB}$.
- Loading `mobimind_hybrid_10m` (37.12 MB file) yielded a peak RSS of $40.60\text{ MB}$ ($\Delta = 34.05\text{ MB}$).
- Loading `standard_transformer_50m` (192.26 MB file) yielded a peak RSS of $195.93\text{ MB}$ ($\Delta = 189.51\text{ MB}$).
- This confirms that the model weights and runtime execution structures are genuinely resident in the physical device's RAM.

### 3. The Activation Explosion in Recursive Architectures (ALBERT)
While ALBERT architectures achieve compact on-disk footprints via cross-layer parameter sharing, the physical execution on device revealed severe runtime overheads:
- **Graph Unrolling & Activation Buffers**: To execute 12 recursive passes, ONNX Runtime allocates intermediate activation buffers that expand peak RSS to **2,208.66 MB (2.2 GB)** for `albert_50m`.
- **Load Time & Cold Start**: Model initialization required **6.72 seconds**, with cold-start inference taking **2.53 seconds**.
- **Conclusion**: Parameter sharing is advantageous for storage-constrained deployments, but without aggressive activation recomputation, it imposes extreme memory and cold-start penalties on mobile runtimes.

### 4. Semantic Convergence Realities & Motivation for Distillation
Training 10M–50M architectures from scratch on 1,000 synthetic contexts resulted in test accuracies between **30% and 50%** (and catastrophic collapse to 0% on `mobilebert_50m` with validation loss 4.04).
- **Hypothesis**: Direct training of high-capacity models on limited mobile action corpora without pre-training is highly sample-inefficient and prone to optimization failure.
- **Scientific Direction**: Rather than attempting end-to-end training of larger models from scratch on device, the natural path forward is **Milestone v0.4: Knowledge Distillation**, using an established foundation teacher (e.g., Llama-3 or Gemma) to supervise the compact MobiMIND student architectures, followed by **Milestone v0.5: INT8 Quantization**.
