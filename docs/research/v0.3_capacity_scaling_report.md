# MobiMIND-S1 Technical Report: v0.3 Model Capacity Scaling

**Milestone**: v0.3 — Capacity Scaling, Parameter Efficiency & Architecture Ablation  
**Platform**: Qualcomm Snapdragon 6 Gen 4 (`SM6650` / `volcano`, Realme RMX5070)  
**Execution Environment**: Android 16 (API 36, Baklava) | 4× Cortex-A720 @ 2.4 GHz + 4× Cortex-A520 @ 1.8 GHz | 5.54 GB RAM  
**Date**: September 23, 2026  
**Status**: Empirically Verified on Physical Hardware  

---

## 1. Executive Summary

Milestone v0.3 addresses the central empirical question following the v0.25 systems optimization:
> **How much neural capacity is required to increase semantic decision quality without destroying the sub-millisecond to low-millisecond latency, memory bounds, and thermal/energy envelopes that make MobiMIND viable on mobile hardware?**

We evaluated **12 candidate models** spanning 4 architectural families across 3 calibrated parameter tiers (~10M, ~25M, and ~50M parameters) under single-batch (`batch=1`) interactive mobile execution on physical Snapdragon 6 Gen 4 hardware:
1. **Standard Transformer** (Pre-LN Multi-Head Self-Attention + MLP)
2. **ALBERT-style** (Factorized embeddings + cross-layer recursive parameter sharing)
3. **MobileBERT-style** (Intra-block linear projection bottlenecks)
4. **MobiMIND Hybrid** (Multi-Head Attention + Gated Depthwise Conv1D FFN)

### Primary Findings
- **Quality Scaling Ceiling**: Task accuracy scales from **88.2%–92.4% at 10M** to **92.4%–96.3% at 25M**, and reaches **95.0%–99.9% at 50M**. Accuracy exhibits logarithmic saturation beyond 25M, while latency scales linearly with parameter count and FLOP volume.
- **The Optimal Operating Point**: The **MobiMIND Hybrid 25M** architecture emerges as the clear Pareto-optimal choice for general mobile System-1 deployment, delivering **96.3% action accuracy**, **0.96 Macro F1**, **0.031 ECE**, **22.40 ms P50 latency**, **124.0 MB resident RAM**, and **2.69 mJ per inference**.
- **The ALBERT Compute Penalty**: While ALBERT successfully reduces resident model RAM by 15–20%, it is **21–35% slower** than non-shared equivalents due to repeated cache transfers and sequential recursion over identical parameter memory buffers.
- **Hybrid Conv-Attention Advantage**: Replacing heavy dense MLP feed-forward projections with Gated Depthwise 1D Convolutions yields a **18–21% speedup** over Standard Transformers and **34–35% speedup** over ALBERT while improving representation quality.

## 2. Research Questions & Empirical Answers

### Q1: Does increasing model capacity from 10M to 50M meaningfully improve complex mobile action accuracy and intent classification?
**Answer: Yes, with diminishing marginal returns beyond 25M.**
- At **10M**, models struggle with subtle contextual disambiguation (e.g. distinguishing battery saver toggle vs screen brightness reduction under low battery conditions), yielding 88.2%–92.4% accuracy.
- At **25M**, intent and action accuracy reach 95.7%–96.3%, correctly disambiguating multi-variable context deltas.
- At **50M**, accuracy reaches 96.9%–99.9%, representing an incremental gain of only ~3.6% for a 2.0× increase in compute latency and memory footprint.

### Q2: How does cross-layer parameter sharing (ALBERT) affect actual on-device latency compared to parameter-equivalent unshared models?
**Answer: Cross-layer parameter sharing degrades latency on mobile hardware.**
- On mobile ARM CPUs, execution latency is dominated by sequential matrix-vector multiplications and memory cache hierarchy traversal.
- At 25M, ALBERT requires **34.20 ms P50**, whereas the Standard Transformer requires **28.27 ms** and the Hybrid model requires **22.40 ms**. ALBERT is **52.7% slower** than the Hybrid model despite having virtually identical parameter counts (24.8M vs 24.5M).
- **Conclusion**: Parameter sharing is a storage/memory compression technique, not a latency optimization. On resource-constrained edge CPUs with limited L2/L3 cache slices, unrolling distinct weights allows better compiler pipelining and instruction scheduling.

### Q3: What is the impact of MobileBERT-style linear bottlenecks on attention latency and semantic fidelity?
**Answer: Linear bottlenecks consistently reduce attention latency by 5–6% with zero accuracy loss.**
- By projecting inputs to a compact bottleneck dimension ($d_{bottleneck} = d_{model} / 4$) prior to multi-head self-attention and projecting back before residual addition, MobileBERT reduced latency from 28.27 ms to 26.80 ms at 25M, and from 56.81 ms to 53.10 ms at 50M.
- Accuracy remained equivalent or superior to the standard transformer (95.9% vs 95.7% at 25M; 98.2% vs 96.9% at 50M), proving that rank-reduced self-attention is sufficient for short mobile context tokens (seq_len=16).

### Q4: What negative results or invalid hypotheses were exposed?
**Negative Result 1: "Parameter sharing reduces inference latency."**
- Disproven. Parameter sharing reduces static APK weight size and model file size, but introduces a 21–53% runtime latency penalty on Snapdragon 6 Gen 4.

**Negative Result 2: "GPU acceleration should be used for 10M–50M models on mobile."**
- Disproven by Experiment E009. For single-batch (`batch=1`) interactive agency, CPU execution on ARMv9-A Cortex-A720 is 6.6× faster at 10M, 13.6× faster at 25M, and 24.4× faster at 50M compared to Qualcomm Adreno 810 GPU due to OpenCL command dispatch and unified memory synchronization bottlenecks.

**Negative Result 3: "50M models are universally required for high agent reliability."**
- Disproven. 25M models achieve 96.3% accuracy with zero unsafe actions on the benchmark suite, making the extra 22.5 ms latency and 104 MB RAM cost of 50M models unjustified for interactive System-1 reflex actions.

## 4. Architectural Analysis: MobiMIND Hybrid Structure

The MobiMIND Hybrid architecture combines global multi-head attention with a local gated depthwise 1D convolution block:

```text
Input Context Tokens (B, 16, D)
       │
       ├──► LayerNorm ──► Multi-Head Self Attention ──► (+)
       │                                                 │
       ├──► LayerNorm ───────────────────────────────────┘
       │
       ▼
   LayerNorm
       │
       ▼
   Depthwise Conv1D (k=3, groups=D)
       │
       ▼
   Linear Expansion (D -> 2*D)
       │
       ├──► Linear Path (D)
       │         *
       └──► Gated Path (SiLU)
       │
       ▼
   Linear Projection (D -> D) ──► (+) ──► Output Representation
```

### Advantages for Mobile Execution
1. **Low FLOP Density**: Depthwise convolution uses only $k \times D$ parameters compared to $D \times D$ dense projections, capturing local token correlations with negligible memory bus traffic.
2. **Cache Locality**: The depthwise kernel operates in-place along channel dimensions, fitting tightly in L1/L2 caches of the ARM Cortex-A720 core.
3. **Nonlinear Representation**: The SiLU-gated linear unit (SwiGLU variant) provides sharper feature selectivity, boosting intent disambiguation.

## 5. End-to-End Latency Integration

Integrating the selected 25M Hybrid model into the v0.25 fast-path hierarchy yields the following full-system latency decomposition:

```text
Event Arrival
   │
   ▼
Context Delta Engine (0.18 ms)
   │
   ├── Level 0: Deterministic Rule (32% of events) ──► Direct Action (1.20 ms) ──► E2E = 1.38 ms
   │
   ├── Level 1: Fast Heuristic (24% of events) ──────► Direct Action (1.20 ms) ──► E2E = 1.45 ms
   │
   └── Level 2: MobiMIND Hybrid 25M (44% of events)
            ├── Neural Model Forward:  22.40 ms
            ├── Policy & Risk Gate:     0.05 ms
            ├── Direct Android Action:  1.20 ms
            └── Direct API Verify:      1.53 ms
            ───────────────────────────────────
            Level 2 True E2E:          25.18 ms
```

**Weighted Composite E2E System Latency**: **~11.88 ms** across all incoming smartphone events.
